// Services / Bridges

Bridges have lost more to exploits than any other category in crypto.

Ronin, Wormhole, Nomad, Multichain. Billions of dollars in losses, across the same category. The reason isn't sloppy code. It's that bridges combine the trust assumptions of two chains with message-validation logic almost nobody else writes. Every bridge invents its own threat model. That threat model gets audited fewer times than the contracts that use it.

Most audit firms treat bridges as smart contract audits: review the L1 contracts, sign off on the relayer interface, ship. The actual attack surface is the system.

// Attack surface

Where the bugs hide.

01

Signature verification

Validator set rotation, threshold signing schemes, and key management flaws that let an attacker forge messages or replay them across chains.

02

Message replay

Cross-chain replay protection that breaks under reorganizations or message reordering. The same valid message executed twice drains funds.

03

Asset accounting

Lock-and-mint logic, supply tracking, and the path between chains where balances can drift if even one assumption is off.

04

Async finality assumptions

Source chain reorgs and finality gaps that let already-relayed messages get unwound, leaving funds minted on the destination but no longer locked at the source.

05

Validator and oracle compromise

Trust models that fail if a threshold of validators or oracles collude or get compromised. Most bridge security comes down to this assumption.

06

Escape hatches and emergency procedures

Mechanisms that exist to recover from failure but introduce new exploit paths if their authorization or sequencing is wrong.
