// Services / L2 Infrastructure

L2 security spans more than smart contracts.

Layer-2 infrastructure combines smart contract security with deeper system-level concerns: sequencer logic, proof systems, data availability, escape hatches, validator and operator behavior. The contracts on L1 are only part of the attack surface. The Rust or Go binary running the sequencer, the zk circuit verifying state transitions, the data availability layer storing transaction batches — all of these can fail in ways that drain user funds without the L1 contracts ever appearing exploitable.

Audit firms that only review Solidity miss most of this. Manual review across the full stack — circuits, sequencer code, L1 contracts — is so expensive that few teams do it before mainnet.

// Attack surface

Where the bugs hide.

01

Sequencer correctness

Ordering, censorship resistance, and escape hatch enforcement that determine whether users can exit independent of the operator.

02

Proof system bugs

Constraint underdetermination in zk circuits, malleability, and edge cases in fault proofs that let invalid state transitions through unchallenged.

03

Data availability

Assumptions about what data must be published, and what fails — silently or otherwise — if it isn't.

04

L1 bridge contracts

Deposit and withdrawal correctness, including the path where withdrawals depend on proof system output rather than direct contract logic.

05

Operator key management

Sequencer keys, prover keys, and multi-sig setups for upgradeability, where centralized failure becomes systemic risk.

06

State root validation

Whether state roots committed to L1 actually reflect verifiable computation, or whether the verifier accepts roots it shouldn't.
